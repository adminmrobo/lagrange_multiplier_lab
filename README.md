# 좌표로 본 라그랑주 승수 — 울타리 안의 최적점

공개 주소: https://adminmrobo.github.io/lagrange_multiplier_lab/

「좌표축 위의 그릇 — 3D 지도로 본 모델 최적화」([optimization_3d_map](https://adminmrobo.github.io/optimization_3d_map/))의 독립 챕터입니다. 울타리(제약)가 있는 최적화를 **좌표평면과 미분으로 함께** 봅니다. 공장의 최적 노동·자본 투입점과 회귀의 릿지·라쏘가 같은 그림(등고선이 울타리에 닿는 점)으로 풀립니다.

## 진행

하루의 첫 발표 — 인턴 시아·모아가 조수 하루에게 질문하고, 방청석의 미공개 식구 셋이 긴장한 하루를 걱정하고, 초파리 연구원·주판봇이 돕고, 박사가 단계마다 정리합니다. 위쪽의 "하루의 긴장도"가 읽을수록 풀립니다.

| 단계 | 내용 | 복습·시연 대시보드 (조건 바꾸기 + 미션 자동 판정) |
|---|---|---|
| 1 | 등고선과 기울기 화살표 | 다른 그릇에서 화살표를 돌려 가장 가파른 쪽·높이가 안 변하는 쪽 찾기 |
| 2 | 원 울타리 위의 x + y — 같은 답, 세 가지 길(각도 미분 · 직선 밀기 · 화살표 나란히), λ = 0.707 | 목표 a·x + b·y를 바꿔 가장 높은 점과 λ 입력 |
| 3 | 공장 16톤을 가장 싸게 — 등량선과 비용 직선 | 임금·사용료·목표를 바꿔 비용 직선 닿게 하기, 사람 수 읽기 |
| 4 | 미분으로 같은 답, λ = 한계비용 7.07 | 만 원당 생산 맞추기, λ 예측 |
| 5 | 회귀(매장 네 곳)의 울타리 없는 경사하강 | 학습률을 골라 8걸음 안에 바닥으로, 발산 관찰 |
| 6 | 왜 보통 회귀가 아니라 릿지인가 (보통 회귀 = λ 0인 릿지, KKT, AI 판단 코너) | 바닥을 옮겨 λ = 1인 반지름, λ = 0이 되는 반지름 |
| 7 | 릿지의 두 길 — 되돌림 경사하강과 벌점 경사하강 | 반지름이 바뀔 때 두 길을 만나게 하는 벌점 세기 |
| 8 | 라쏘는 왜 이 방법으로 안 되나 (모서리, w₂ = 0) | w₂ = 0인 구간과 울타리가 풀리는 순간 |
| 대결 | 내려간 뒤 잘라 붙이면 될까? → 초파리 승 | 그릇 길쭉함에 따른 잘라 붙이기의 오차 |

정리 표 옆에 복습 미션 기록(17개)이 모입니다. 기록은 저장하지 않습니다.

## 파일

```
index.html                 빌드 결과 (단일 파일, 외부 라이브러리 없음)
build/
  page.src.html            본문·대사·실험·복습 대시보드
  lagmath.js               계산 모듈 (본문 예시 + 복습용 일반식)
  common.css · common.js   연구실 공통 디자인·도구 (optimization_3d_map에서 가져온 판)
  sprites96.js · sprites_extra.js  캐릭터 표정 (fruitfly-lab-expressions, 96px)
  kgx.js · backbone.json   지식 색인·꾸러미
  kg.json · refs.json · meta.json
  build.js                 node build/build.js → index.html
code/check_lagrange.js     숫자 검산 (node code/check_lagrange.js)
COVER_PROMPTS.md           픽셀풍 표지·장면 그림 지시문 (img/ 에 넣을 이름 포함)
img/                       표지(cover·cover_960)와 장면 그림 7장 (16비트 픽셀아트, 젠스파크)
```

숫자는 모두 설명용 예시입니다. 캐릭터 이름·설정·그림은 저작권자 안상선의 허락 없이 사용할 수 없습니다.
